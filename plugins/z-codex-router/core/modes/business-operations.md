# Business Operations

## 适用范围

运营、商务、预算、品牌、活动、客户研究、提案、报价、合同与对外沟通材料。agent 可准备事实、草案、检查清单和建议，不能作为审批人、法务、财务、签字人、承诺主体或账户权限主体。

本 mode 只提供运营与商务任务的映射示例；Tier 仍按 router 的统一判定轴和顺序决定。

## 任务类型到 Tier

| 任务 | Tier |
| --- | --- |
| 已给定数据的只读整理、排期或固定格式材料检查 | A0 |
| 明确边界的小型活动文案、预算表或提案修订 | A1 |
| 目标、受众、渠道、预算和验收明确的活动方案、运营分析或商务材料 | B0 |
| 多渠道、多客户或多阶段运营/商务计划整合 | B1 |
| 多系统运营、复杂预算归因、合同依赖或跨区域协同 | B2 |
| 目标、商业取舍、报价策略、品牌方向或谈判立场未定 | C1 |
| 范围很大且需要长期自主统筹的运营规划 | C2 |
| 法务/财务/隐私/安全风险、支付、合同、账户或外部不可逆动作 | C3 |

## 检查与验收证据

运营方案应明确目标、人群、渠道、品牌约束、排期、预算、指标、负责人、上线监控、止损条件和复盘方式。客户研究、提案、报价、合同和谈判材料要区分已核实事实、可谈范围、待确认条款与不可作出的承诺。

验收材料需列出适用的法务、财务、品牌、安全与隐私审批，以及发布确认、撤回/止损预案。对外发送、签署、支付、采购、账户/权限变更和公开发布，均须由具备相应权限的人明确确认并实际执行；agent 不得替代该确认或执行。

## 环境阻塞

缺少预算口径、品牌规范、合同/报价基线、审批结果、客户授权或对外渠道权限时，只能交付草案与待确认项。任何不可逆或外部副作用不得因文档已准备而自动发生。
