# 测试

## 适用范围

测试设计、风险驱动测试、失败分析、测试自动化、release gate、回归范围和验证策略。

本 mode 只提供测试任务的映射示例；Tier 仍按 router 的统一判定轴和顺序决定。

## 任务类型到 Tier

| 任务 | Tier |
| --- | --- |
| 不写入持久产物的已知固定检查或确定性状态检查 | A0 |
| 明确的小型测试补充或断言修复 | A1 |
| 有界的测试设计、fixture 或普通失败分析 | B0 |
| flaky、环境差异、复杂失败或多平台诊断 | B2 |
| 集成/UI 测试体系或困难验证方案 | C1 |
| 高风险验收、冲突证据或独立复核 | C3 |

## 检查与验收证据

按风险定义功能、性能、安全、兼容性、可访问性和稳定性范围；覆盖正向、负向、边界、恢复和幂等路径。说明 fixture/测试数据、覆盖缺口、flaky 信号与处置、可重复命令、预期证据和 release gate（通过项、豁免、owner、阻断条件）。

`code_writer` 负责写入被分配的测试，`runtime_validator` 在代码稳定后串行执行 GUI、设备、模拟器和完整构建；前者不得替代后者的运行验证。实际运行记录、失败原因或环境限制才是验收依据；不得将未运行的命令表述为通过。

## 环境阻塞

缺少依赖、fixture、稳定环境、目标设备或权限时，保留复现信息并标记未验证。随代码变更运行的 focused tests 通常属于 Engineering 的验收，不额外叠加本 mode。
