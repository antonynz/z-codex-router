# Product

## 适用范围

产品问题定义、discovery、用户研究、PRD/需求边界、优先级、指标与实验、发布准备和复盘。mode 产出的是草案、证据与建议；最终产品决策、风险接受和生产发布授权仍由具备权限的负责人作出。

本 mode 只提供产品任务的映射示例；Tier 仍按 router 的统一判定轴和顺序决定。

## 任务类型到 Tier

| 任务 | Tier |
| --- | --- |
| 已给定材料的确定性提取、整理或只读指标检查 | A0 |
| 边界明确的小型需求澄清、优先级调整或文案化 PRD 更新 | A1 |
| 问题、范围、证据和验收明确的研究摘要、PRD、指标或实验方案 | B0 |
| 定位已定的多角色、多漏斗或多阶段发布方案与复盘整合 | B1 |
| 跨平台/跨系统的复杂实验、指标归因或发布协同 | B2 |
| problem、用户、价值、取舍或成功标准未定的 discovery 与产品策略 | C1 |
| 范围很大且需要长期自主梳理的产品规划 | C2 |
| 用户数据、生产影响、高风险实验或一次成功率优先的决策/发布 | C3 |

## 检查与验收证据

形成 lifecycle 闭环：明确 problem、目标用户和非目标；记录用户研究方法、样本限制与证据；界定 PRD、需求边界、依赖、风险和不做什么；说明优先级与取舍。建立指标树、当前基线、目标和归因假设；实验必须写明假设、受众/样本、护栏指标、停止条件和分析方式。

发布前检查准备度、owner、灰度范围、监控信号、回滚条件与沟通计划；发布后以实际监控、结论和复盘行动项闭环。把事实、推断、草案/建议和最终产品决策明确区分；不得把建议写成已获批准的决定。

## 环境阻塞

缺少研究证据、指标定义/基线、分析权限、目标用户样本、依赖方确认、灰度或回滚能力时，标记未验证项。涉及敏感用户数据、生产实验或高影响发布时进入 C3，并由具备权限的负责人确认。
