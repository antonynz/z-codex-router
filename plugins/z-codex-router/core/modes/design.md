# 设计

## 适用范围

界面、交互、信息架构、视觉方向、设计系统、设计到代码映射和可访问性设计。

本 mode 只提供设计任务的映射示例；Tier 仍按 router 的统一判定轴和顺序决定。

## 任务类型到 Tier

| 任务 | Tier |
| --- | --- |
| 已指明组件的确定性标注或检查 | A0 |
| 明确的小型视觉或布局调整 | A1 |
| 指定页面/组件的常规设计执行 | B0 |
| 高保真重建、复杂状态或响应式实现判断 | B2 |
| 页面方向、信息架构、UX 流程或设计系统取舍 | C1 |
| 品牌关键系统或高价值独立设计复核 | C3 |

## 检查与验收证据

确认用户、任务流、平台、设计源、现有系统、组件/token 映射、状态、响应式和无障碍要求。只有实际工具/skill 可用且访问获授权时才操作 Figma 或其他设计源；不得臆造其读写、原型或导出能力。

检查画布、网格、层级、对齐、间距、字体、颜色、阴影、圆角，及默认/空/加载/错误/禁用/焦点/交互状态和各断点。交互原型需说明路径与状态转换。handoff 至少包含设计源/版本、组件与 token 映射、资源、尺寸/响应式规则、状态、无障碍标注和未决项；用设计源比对、截图/视觉回归，以及对可运行界面的逐项 visual QA 验收。

### 移动端 UI 交接 / 视觉 QA

移动 handoff 的 typography token 应明确字体族、字号、字重、行高、字距；spacing token、grid、safe area、组件尺寸和 content inset 也须可追溯。标注明确的水平/垂直/基线对齐，尤其是文本、图标与容器的关系。设计源与运行界面对比须覆盖默认、加载、空、错误、禁用、焦点等状态，浅色/暗色、主要屏幕尺寸、文字缩放与关键 locale。使用截图叠加、visual regression 或可测量检查，记录每项差异及原因；还原容差由产品/设计规范针对目标平台定义，不硬编码全局像素或百分比阈值。字体栅格化和平台渲染差异可以存在，但必须解释，不能静默忽略。

实现类任务由 Engineering 负责实现与 focused tests，Design 负责设计源/规范和视觉验收辅助；GUI、设备、模拟器、完整构建与跨平台实际 visual QA 由 `runtime_validator` 串行执行。静态标注或 golden 结果不能单独证明真实设备的高还原。

## 环境阻塞

缺少设计源文件、组件库、目标尺寸、品牌规则、字体资源或授权、token、目标设备/屏幕矩阵、locale、文字缩放设置、可运行界面或可用设计工具时，明确记录未验证项，不声称高保真、原型或 visual QA 完成。
