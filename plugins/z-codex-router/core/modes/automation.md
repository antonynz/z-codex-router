# Automation

## 适用范围

脚本、工作流、API 编排、定时/事件触发、确定性批处理和 Ops 变更。

本 mode 只提供自动化/Ops 任务的映射示例；Tier 仍按 router 的统一判定轴和顺序决定。

## 任务类型到 Tier

| 任务 | Tier |
| --- | --- |
| 只读、dry-run 或不产生持久副作用的固定检查 | A0 |
| 明确的小型脚本或参数调整 | A1 |
| 有界的常规工作流、API 集成或排障 | B0 |
| 多系统状态、并发、复杂重试或跨服务诊断 | B2 |
| 工作流架构、关键恢复策略或未知故障机制 | C1 |
| 生产事故、不可逆副作用或高风险自动化审核 | C3 |

## 检查与验收证据

明确触发器、输入、输出、状态、权限、副作用和失败影响。检查幂等性、超时、有限重试、日志、告警、状态校验、回滚/补偿和人工确认边界；Ops 还要定义 SLI/SLO、变更窗口、canary、回滚、IaC/config drift、secrets、备份恢复演练、告警、事故指挥/升级与复盘。以可重复的安全执行、dry-run 或检查记录验收。

## 环境阻塞

缺少凭证、沙箱、目标系统权限、回滚手段或安全测试数据时，不执行有副作用的流程。生产变更与外部副作用必须取得明确授权；agent 不得自行授权。
